# 2.1.3 主线评估与下一轮路线

审查基线为已发布 `v2.1.2`（`8b5c6a2`）。原工作区未提交的 RAW、主题、内存和相机改动不视为本轮基线，也没有纳入候选包。竞品源码与许可证证据见[调研](RESEARCH.md)，验证结果见[验收报告](TEST_REPORT.md)。

## 能力清单

| 面向用户的能力 | 实现与依赖 |
| --- | --- |
| 移动胶片摄影 | Kotlin / Compose，CameraX + Camera2；前后镜头、对焦测光、闪光、ISO/快门、曝光补偿、白平衡、手动对焦、变焦、倒计时、音量键和三／五张拍摄。厂商人像、HDR、夜景可用性随镜头；主线只保存 JPEG。 |
| 取景与显影 | 20 种风格、样片与强度、网格、水平仪、直方图、峰值、明暗警告；低频取景分析与 CPU 色彩引擎、全尺寸 sRGB 输出，有内存限额和失败保留原图。 |
| 作品库 | 系统照片选择器与逐张授权、原片／成片对照、收藏、分享、撤销编辑／移除、另存版本；MediaStore 存照片，SharedPreferences JSON 保存版本与偏好，不依赖服务器、SQL、账号或网络图像上传。 |
| 平台与安全 | API 29 起；系统安全区、横屏、宽窗口与折叠避让。更新仅查询固定 GitHub Release，核对摘要、包名、版本、证书和最低 API，交系统确认安装。 |
| 工程与分发 | Gradle Wrapper / AGP / JDK 21；单测、Debug／Release Lint、API 29／35 仪器、平板安全区；标签必须在默认主线中，签名和公开资产通过现有 Actions 门禁。 |

## 问题与优先级

| 优先级 | 问题／证据 | 行动与验收 |
| --- | --- | --- |
| P0 | 未确认有导致全体用户无法启动或实际媒体丢失的发布阻断问题；不等于完整安全证明。 | 保留双 API、签名、安装启动与公开摘要门禁。 |
| P1 · 本轮 | `MainActivity.kt` 原先整条路由依赖相机授权，拒绝权限也无法进入作品库或设置。 | 把权限收窄至取景器。实测无权限冷启动与 UI 回归；保留授权下的拍摄、相册、渲染回归。 |
| P1 | `CameraOutput.kt` 和 `PhotoEnhancementEngine.kt` 先后发布原片、成片，再更新索引；进程中止时没有恢复对账。 | 先增加持久状态与启动时对账，注入两处进程死亡，确保不删除媒体且不重复生成；再评估索引迁移。 |
| P1 | `CameraScreen.kt` 连拍每张等待全尺寸渲染返回；成片失败还会停止下一张。 | 以原片可用与成片可用分别埋点，在相同设备度量快门间隔 P50/P95 和内存，验证有界队列、失败后的后续拍摄与原片保留。 |
| P2 | `CameraScreen.kt` 重绑可清空同镜头手动参数，三分网格只保留黄金分割偏好。 | 分离会话重绑与用户设置，按能力重新校验原值，验证前后台、画幅、镜头切换、设置返回。 |
| P2 | `GalleryScreen.kt` 返回会丢未保存调整；旧版只有成片时，直接保存可能重复套色；URI 失效只显示通用预览错误。 | 先做未保存提示和“以当前成片为基底”回归；再提供失效来源的重选，不自动改绑用户图片。 |
| P2 | `CameraController.kt` 未用共享 ViewPort；`FilmColorEngine.kt` 对预览与成片各自估计场景。模拟器的手动曝光测试允许硬件不符跳过。 | 同一靶图比画幅边缘、旋转、前后镜头及固定输入的颜色；真机区分“不支持”和“声称支持但未生效”。 |
| P2 | `.github/workflows/release.yml` 在已有草稿时重跑不能恢复；`UpdateViewModel.kt` 自动检查失败也会写入检查时间。 | 发布区分无 Release、待验证草稿、已公开三个状态，复查摘要后才继续；更新计时单独记录成功与暂时失败，补 HTTP 和签名拒绝测试。 |
| P3 | 没有大库规格下的缩略图延迟与内存基线，系统备份策略和分享时原图 EXIF 行为也需要确认。 | 先用独立 500 项合成库测量；再为 URI 重绑、备份和可选去除敏感 EXIF 设计兼容测试。 |

## 自有包静态暴露面

1. **总览**：用 Android 静态扫描对比两个公开签名包，2.1.3 相对评分 98/100（B），与 2.1.2 相比无新增告警。评分不是安全认证。
2. **发现**：`allowBackup=true`（低，沿用现有策略）；开源应用的 DEX 可读，不靠混淆保护授权。未签名的本地中间包不用于分发。
3. **证据与验收**：`apksigner` 验证两个公开 APK 的 v3 签名和同一证书，`aapt` 确认 2.1.3 的包名、版本码 7、minSdk 29 与非 debuggable 状态；详见[发布历史](../RELEASE_HISTORY.md)。备份标志不能证明所有系统都允许 adb 提取数据，不在未验证迁移影响时盲目关闭。
4. **客户端无法解决**：客户端含开源图像算法，不包含用于授权或计费的长期凭证；正式证书可公开，正式签名私钥始终只在发布环境中使用。
5. **修复顺序**：先维持签名和更新校验，再验证数据迁移、备份与恢复策略，最后考虑是否值得增加构建产物加固；不对正常调试或可访问性加限制。
