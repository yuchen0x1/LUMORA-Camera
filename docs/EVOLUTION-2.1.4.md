## 五、问题发现与本轮选择

1. **离线失败阻断更新恢复。** 旧代码在网络结果前写入混合的尝试时间，周检查可能因一次失败推迟七天。问题明确、改动边界小、有纯策略回归路径，优先修复。
2. **错误只在设置页显示。** 下载/安装失败变成 Notice，但相机/图库根界面未呈现，用户无法理解或恢复。
3. **关闭后的安装竞态。** 校验挂起期间选择“稍后”，迟到结果仍可能启动安装器或重新打开错误。独立审查发现后补齐取消和两个返回路径的活动性校验。
4. 另确认三分网格持久化、旧版仅成片编辑基线、持久 URI 授权回收等问题，但未混入本轮发布。详情与优先级见 [问题清单](../AUTONOMOUS_ISSUES.md)。

## 六、实现与变化范围

- 新建 `UpdateCheckPolicy`：成功检查才更新每日/每周周期，失败使用独立 15 分钟退避；边界到期可检查，未来时间戳不永久压住请求。默认仍仅手动检查。
- 自动检查仍由前台恢复触发，不是后台定时器；15 分钟后需要下一次前台触发。手动检查可立即重试，不新增 HTTP 自动重放、指数退避或 Retry-After 解析。
- 提取 `UpdateClient` 接口，给 ViewModel 注入客户端、私有偏好与时钟用于隔离测试，保留生产 Application 构造入口及原有网络/身份校验。
- 根级 `UpdateDialog` 呈现 Notice，设置页不再重复显示同一错误；未确认的提示不被自动前台检查覆盖。
- Ready 状态选择“稍后”先取消校验任务再清理文件；启动安装器前及普通错误处理前均执行协程活动性校验，避免成功/失败迟到回调越过关闭操作。
- 新增 6 项 JVM 策略、12 项真实 JSON 协议和 11 项状态/UI 回归。更新版本、变更日志、能力/研究/验收/问题与维护记录，并保留真实断网截图。
- 无数据迁移、无外部付费服务更改、无生产签名或来源规则放宽。

## 八、发布产物安全复核

### 1. 总览

对自有未签名中间 APK 和公开正式 APK 使用相同暴露面扫描器做基线比较。正式包启发式分数为 98/100、等级 B，输出低风险 1 项及提示 3 项；分数只用于相对排序，不是安全证明。中间产物的签名缺失项在正式签名包消失，这是交付验证，不是宣称旧正式版曾未签名。

### 2. 发现清单

| 编号 | 级别 | 证据与含义 |
| --- | --- | --- |
| APK-SIG | 中间产物高风险，正式包已消失 | 公开 APK 经 apksigner 验证 v3 成功，单一稳定证书；没有交付未签名 APK。 |
| APK-ALLOWBACKUP | 低，仍存在 | 公开包 Manifest 的 `application@allowBackup=true`；具体备份/导出能力取决于 Android 版本、目标 SDK 与设备策略，不等于任何设备都可直接导出。 |
| APK-DEX | 信息 | 三个 DEX 可被分析；项目为 MIT 开源，不应把本地算法或客户端校验当秘密。 |

### 3. 逐项证据与修复

最终密码学结论采用 `apksigner verify --verbose --print-certs`：v3=true、v2=false、证书指纹与上版/元数据一致；扫描器的签名块识别摘要不能替代验签。备份候选需要先盘点作品索引、更新缓存、URI 权限与恢复期望，再制定 `dataExtractionRules`/备份规则并测试恢复，不为消掉低风险提示盲设 false。公开包经 aapt 确认非 debuggable，zipalign 检查成功。

原有固定来源、资产摘要、大小、APK 身份及同证书校验未削弱。协议负向测试不代替 APK 验签，且未声称扫描覆盖所有库/运行时行为。扫描比较的本机原始记录为 `build/exposure-214.json` 与 `build/exposure-214-signed.md`。

### 4. 客户端无法解决的问题

随 APK 下发的长期密钥、付费授权最终决策或秘密算法无法靠混淆保密；如未来引入此类服务，应采用服务端判定与短期凭证。当前工程无自建付费/订阅后端，不凭空认定存在授权绕过，也不为 MIT 开源算法增加侵入性反调试。签名私钥继续仅由受保护发布环境使用，未写入源码或报告。

### 5. 修复顺序

本次扫描范围没有遗留的严重/高风险发现，但不是全系统无漏洞保证。后续先保留现有签名/更新门禁，再评估备份恢复策略；DEX 混淆收益低于数据正确性、取消和生命周期验证。2026-11-21 查询的开放 Dependabot 告警为 0，不等于所有传递依赖绝对安全。
